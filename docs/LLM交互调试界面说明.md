# LLM 交互调试界面

在桌面程序点击 **LLM 交互调试** 打开。现有 `tools/start-decision-monitor.ps1` 和 `--monitor <session.json>` 入口继续有效。

主视图按“存档 + 会话 + 决策ID”归组，左侧最新在上。可搜索触发原因、模型、决策ID和工具名称，也可筛选含失败/拒绝的决策或季节维护。

右侧先选择请求轮次，再查看：

1. **发送给模型**：该次实际请求里的 System、结构化上下文和工具列表；按目标、世界、工作状态、项目等部分展开。这里不是不断更新的最新世界状态。
2. **回复与工具**：本轮公开回复、工具调用参数、本地返回、耗时及 usage；底部可展开该次实际发出的消息序列，包括历史 assistant/tool 消息和调用ID。
3. **实际执行**：原生动作派发、任务ID、批次ID、最新回执和批次汇总。进度记录归并到该任务最终回执。
4. **原始请求 JSON**：完整请求捕获，可一键复制。

`accepted` 表示接收任务，`decision_finished` 表示本次模型交互结束；两者都不表示游戏操作已完成。批次/单次执行状态根据原生回执继续更新。失败、等待条件变化、等待玩家回答和未选择动作重试各自展示。

点击历史决策会停止自动跟随；手动选择旧请求后，新事件也不会把轮次切走。“回到最新”清除筛选并恢复跟随。原始事件、规划成果、阻塞事件、长期目标及最近模型输入保留在其他页签。

日常决策、季节维护和离线聊天共用请求捕获与轮次展示。离线聊天仍然不提供游戏工具；其输入以实际发出的文本为准，不拿调试辅助上下文代替真实请求。

内存最多保留80个决策分组，每组最多300条事件。完整请求单独保留，运输重试按 requestId 合并并显示发送次数。若日志从中途载入或部分事件已移出界面，会明确提示，不推断缺失内容或模型内部思考。

验证包括请求快照隔离、轮次关联、历史查看、拒绝筛选、会话隔离、运输重试、accepted/原生完成区分，以及原始进度到终态的替换。界面预览使用本地回归夹具，并非真实游玩数据。
