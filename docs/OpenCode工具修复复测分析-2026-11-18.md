# OpenCode 工具修复复测分析（2026-11-18）

## 目的与结论

本文依据《工具修复交付-Codex测试-2026-11-17.md》整理当前复测证据，供 OpenCode 先分析症状与根因，再决定修改方案。此文不是代码修改授权，也不把未完成或无效夹具写成产品失败。

交付范围为 8 组工具/API 改动、11 个验收用例。当前已有 5 个目标用例进入实机测试：**0 项通过、4 项在有效测试条件下失败、1 项因夹具未解锁 Duck 而无效**。此外，T075-S02 的直接 `/task` 探测使用了不适用的入口，不能算用例结果。其余目标用例尚未完成。

有效复现的问题是：T028-S01 跨图下单超时、T044-S02 动物未迁舍且发生抚摸副作用、T002-S04 节日未离场、T021-S01 正确钓鱼坐标下 3 次抛竿均未被原版注册。以下区分了观察事实、源码事实与尚待验证的解释。

## 有效失败分析

### 1. T028-S01：`order_building(Well)` 跨图路径没有完成

**复现结果**

两次调用都以 `native_action_timeout:order_building` 结束。当前版本复测证据为：

- `.local/solo5/SC112D_20261117_T021B/T028-S01-result.json`
- `.local/solo5/SC112D_20261117_T021B/T028-S01-native-after.json`

复测停在 BusStop（tile 14,8），阶段为 `waiting_for_native_animation`，没有完成木匠处下单，金币仍为 99,975。第一次证据在 `.local/solo5/SC112D_20261117_CODEXTEST/T028-S01-result.json`，同样超时在 `travel_to_shop`。补充 `go_to(Mountain)` 在 BusStop 与 Backwoods 间反复切图，未自行终止，由测试端取消：`T028-go_to-mountain-result.json`、`T028-go_to-mountain-final.json`。

**目前可以确认**：修改后跨图流程仍不能稳定到达目标并完成任务；本次最终错误是超时，并非 `map_transition_bounced`。

**源码线索与待讨论点**：`src/StardewCompanion.Mod/Navigation.cs` 的弹回计数/路线状态重置逻辑值得追踪。单看代码尚不足以断定它是本次超时根因。请先基于每次 warp 的起点、终点、当前位置及 `_mapBounces` 变化，说明为什么路由没有到达 Carpenter、为什么没有在边界内以明确失败终止，再决定是否改代码。不要仅以“放宽次数”作为未经验证的结论。

### 2. T044-S02：迁舍未验证成功，且操作期间动物被抚摸

**复现结果**

- 任务结果：`.local/solo5/SC112D_20261117_CODEXTEST/T044-S02-rehome-result.json`，终态 `animal_rehome_not_verified`，阶段 `approach_native_target`。
- 场景：`.local/solo5/SC112D_20261117_CODEXTEST/T044-S02-scene.json`，来源畜舍 `Coop35bdd094-dedd-4725-867b-eb838545b783`，目标畜舍 `Coop776f57a2-f2f7-4f8f-8338-af909c42f715`。
- `go_to` 能进入来源畜舍并观察到鸡 Tutsi（ID `887711001`）：`T044-S02-go_to-coop-result.json`。
- 原生后置快照 `.local/solo5/SC112D_20261117_CODEXTEST/T044-S02-native-after.json` 显示 Tutsi 仍在来源畜舍，没有迁入目标畜舍。
- 运行前记录为 `petted=false`、好感 100；后置快照为 `petted=true`、好感 115。运行前快照没有单独落盘，所以下次复现应把前置快照也保存为文件。

**源码事实**：`src/StardewCompanion.Mod/NativeWorkCommerce.cs` 约 420–447 行，在没有 `AnimalQueryMenu` 时，会走近动物并调用 `animal.pet(Game1.player)`，然后再继续打开查询菜单。这与后置快照中的抚摸标记/好感变化吻合，是已发现的直接副作用路径。

**仍待确认**：目标畜舍点击是否到达正确世界坐标、游戏是否接收了点击、迁舍菜单选择发生了什么，以及最终 home ID 核验是否读到了预期实体。请先解释为何查询/迁舍流程需要先抚摸动物，以及产品行为是否允许该副作用；再结合点击坐标与原生菜单状态讨论修改。迁舍失败和抚摸副作用应分别跟踪。

### 3. T002-S04：真实节日场景下未离场

**复现结果**

- `.local/solo5/SC112D_20261117_CODEXTEST/T002-S04-leave-result.json` 返回 `event_exit_not_observed`。
- `.local/solo5/SC112D_20261117_CODEXTEST/T002-S04-native-after.json` 显示仍在 `Temp`，`eventUp=true`，时间 09:00，活动未结束。
- 使用真实 `festival_spring13` 活动状态；没有观察到离场。

**源码线索**：`src/StardewCompanion.Mod/NativeWorkProgression.cs` 的出口搜索已覆盖 `Action`、`CheckAction`、`TouchAction`，并按 `Leave`/`Exit` 子串匹配。错误码意味着执行时未找到可用候选，或没有观察到其成功效果。

**证据缺口**：场景请求的 `includeMapActions:true` 当时扫描的是 Town，而游戏事件实际将玩家送入 Temp。因此目前没有保存 Temp 实际地图的 `Action`、`CheckAction`、`TouchAction` 图层内容，也没有确认 Spring 13 活动的出口是否使用脚本事件/warp，而非这些图层。请先在实际 Temp 活动地图采集出口附近的图层动作、位置和事件状态，再判定是候选发现还是执行/验证失败；不要仅凭旧地图扫描推断出口名称。

### 4. T021-S01：有效岸边位置下三次抛竿均未被原版注册

**有效性更正**

旧尝试使用 Beach `(40,25)`，不符合交付验收证据里的有效位置，因此不作为失败证据。交付包已有验收样例确认有效岸边坐标为 Beach `(42,36)`，向下，Training Rod，普通时钟。此次已按该有效位置重新测试。

**复测结果**

- 场景：`.local/solo5/SC112D_20261117_T021B/T021-valid-shore-scene.json`。
- 结果：`.local/solo5/SC112D_20261117_T021B/T021-S01-valid-shore-3casts-result.json`，任务 ID `0ca9530746d94ada993927fde5d384e2`。
- 三竿均出现 `native_cast_started` 后 `native_cast_not_registered`，最终 `no_native_catch_confirmed`；没有观察到 bite、hook 或 catch。体力 270 降至 246，时间 10:00 推进至 10:50。

**源码线索与待讨论点**：`src/StardewCompanion.Mod/SpecialActivityExecutor.cs` 在 `cast_line` 阶段按住 Tool 约 1400ms，释放后发出 `native_cast_started`，等待至 5000ms；若鱼竿状态仍未注册则发出 `native_cast_not_registered`。结果确认有效位置下原版没有进入被当前观察逻辑识别的钓鱼状态，但尚不能区分输入释放边沿没有被游戏接收，还是状态采样遗漏了已开始的抛竿。请检查逐帧按键状态、释放时机、鱼竿状态变化和日志时间序列，再确定根因。
