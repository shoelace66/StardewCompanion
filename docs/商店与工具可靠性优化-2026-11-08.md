# 商店与工具可靠性优化

## 交付范围与验证边界

将皮埃尔的名称购买、营业检查、交互核验推广到其他商店，并逐类检查业务工具、原子动作、查询和计划工具。针对实际发现的目标识别、错误原因、未核验即计数、重复交互和中断进度问题修改实现。

本文记录源码审计与实现结果，不代表实机用例已经通过。按用户要求，本次只做源码核对、编译检查和构建文件同步，不启动游戏、模型调用或春季试跑，不运行测试套件。

## 商店接口

所有 `purchase_items` 购买均使用商品名称。`itemId` 仍是库存、授权工作箱及其他需要精确身份的内部标识，不再用于购买清单。

```json
{
  "location": "FishShop",
  "shopId": "FishShop",
  "maxTotal": 500,
  "items": [
    { "itemName": "Bait", "count": 5, "maxUnitPrice": 5 }
  ]
}
```

名称必须精确匹配真实菜单的本地化显示名或英文内部名。示例只说明参数形状，商品是否出售、价格和库存仍以当前菜单为准。同名商品可选填 `quality`（0、1、2、4）消歧；仍不唯一则拒绝，不按价格、顺序或相似名称自动任选。目录包含名称、内部名称、品质、价格、库存和每份数量。

- 所有真实 `ShopMenu` 的标准物品购买复用同一个名称匹配、预算、库存及入包核验过程。
- 自动接近支持原版 `OpenShop` 柜台，以及皮埃尔、鱼店、桑迪、酒吧、Joja、医院、冰淇淋摊、冒险者公会、铁匠、木匠、牧场、书商、电影院售票处等原版入口。
- 补充旅行货车、帽子店、科罗布斯、岛屿度假酒吧、夜市部分摊位以及沙漠/岛屿交易摊的原版交互目标。只通过原版交互开店，不强制创建商店菜单。
- 同一商店代码出现于多个地点时优先使用请求的真实地图；无法消歧则返回原因，不猜地点。旅行货车森林营业条件不套用到夜市货车。
- 当前打开其他商店且没有鼠标持有物时，先关闭空闲菜单再去目标商店；持有物尚未处理时明确阻塞，不丢弃物品。
- 工具升级通过 `upgrade_tool`，建筑通过 `order_building` / `modify_building`，动物通过 `manage_livestock`。普通购买拒绝升级和未适配的宠物收养服务，避免付费后错误地等待普通物品入包。
- 已有的金币预算合同不扩展为代币或以物易物授权。遇到非金币或额外交易材料时，在付款前明确返回不支持的支付合同。
- 配方以实际解锁变化核验；星之果实以原版永久体力上限变化核验，不把其自动食用过程当作普通库存丢失。

节日 `attend_event(activity="shop")` 使用 `itemName`、正数 `count` 和 `maxCost`；菜单尚未打开时可提供当前活动的真实 `shopId`。节日购买复用普通交易核验，不再按点击次数增加完成量。

## 营业、交互与提示词

| 情况 | 当前处理 |
| --- | --- |
| 尚未开门，距已知开门时间超过30游戏分钟 | 直接返回营业时间及最早进入短时等候窗口的时间，不先跑店 |
| 距已知开门时间不超过30游戏分钟 | 自动接近入口并等候；时间推进由游戏完成，可暂停取消 |
| 当天休息、已关店、节日停业 | 分别返回明确原因；保留周三营业解锁、城镇钥匙等原版例外 |
| 旅行商人、书商不在当天营业日 | 使用游戏原生日期判定，不由模型猜星期或日期 |
| 店员不可用、原版条件未满足 | 根据真实交互与当前原版条件回报，不把店员离开一律认定为停业；保留钱箱、自助购物和动物目录书例外 |
| 营业时间无法确认 | 保持未知，通过原版交互核验；未知不等于关门 |
| 柜台不存在、路径不可达、菜单没有打开 | 分开回报；一次开店最多交互两次，不再返回模糊的“关门或未刷新” |
| 名称不在目录、品质不符、同名不唯一、售罄 | 返回实际目录和具体原因；不推断“这个物品永远不存在” |
| 参数或执行器异常 | 保留具体校验原因；有已核验进度时返回部分完成，不丢弃已成交事实 |

营业时间优先读取柜台 Action；必要时读取原版入口时间，并明确标注“入口时间仍需原版服务核验”。旧版皮埃尔柜台兼容原版09:00–17:00服务窗口。原版已经打开的商店菜单优先作为可交易事实。城镇钥匙可绕过的入口时间不再被误当成柜台营业限制。无法确认下一次营业时间时返回未知，不编造日期。

所有已知需从顾客侧交互的旧柜台统一按正确方向接近。购物先放空手，避免点击 NPC 商人时误送当前手持物。交易和制作点击屏蔽临时 Shift/Ctrl 修饰键，防止一次点击变成批量操作而超过数量或预算。

全局提示词只替换一条购买规则：

> 所有商店及节日购物使用商品名称itemName，注意营业时间和活动影响。技能自动寻路、开店，在已知开门前30游戏分钟内等候；失败按回执和真实目录调整，不猜测、替换或无效重试。其他工具的身份标识须来自观察或实际选项目录，同名不明确时先澄清目标。

原因分类、选项目录和恢复条件按实际回执提供，不作为长篇常驻提示词。失败证据省略无关空字段；未知营业时间仍保留明确的未知状态。

## 实现入口与边界

- `NativeWorkShop.cs`：通用开店、真实目录、支付与商品选择，以及已知原版入口适配。
- `ExecutionTargets.cs`：准确名称解析、目录来源说明、坐标及受限地点检查。角色/建筑定义目录只证明身份存在，不证明当前可交流或已解锁。
- `NativeWorkFailureEvidence.cs`：按错误类型提供真实库存、菜单、工具、建筑、动物、任务及原版提示；不提供编造候选。
- 其余 `NativeWork*`、`BusinessExecutor`、`RoutineExecutor`：各业务动作的结果核验、实时进度和取消时证据。
- `ContractValidation`、`BusinessCapabilities`、Core提示词及失败守卫：名称接口、必要参数、重复失败条件及模型看到的简短规则。

支持范围仍有明确边界：金币购买不自动转成代币/以物易物交易；宠物收养、未适配的小游戏/公共项目及部分任务交付类型不假装执行成功；无法识别的自定义商店入口返回未知/未观察，而不是强行开店。返回不支持时不会先尝试对应付款。
