# 季计划预览与执行前置条件

主前端和 LLM 交互调试窗口均提供“季计划预览”。界面直接读取当前角色保存的模型计划，展示目标版本、计划状态及缺失原因。每日计划功能已移除，不再生成或作为执行前置条件；后续工作由短批次与连续预规划衔接。

## 执行顺序

1. 在 LLM 交互调试窗口的“长期目标”页保存目标，确认出现已保存的版本号。目标为空或已取消时，“继续”返回明确错误。
2. 模型必须调用 `create_season_plan`，保存当前季节的目标、约束、成功条件、阶段日程与资源策略。
3. 季计划有效后，允许派发游戏动作。选择“仅规划”可生成预览；该模式不执行游戏动作。

计划生成使用单独请求，强制选择对应工具。空回复、未调用指定工具、空目标、空数组、空白步骤或缺失预算均不视为计划完成；界面显示受阻原因并等待重试。计划由模型填写，程序不使用默认经营策略补齐。首次计划的实际进度数组允许为空，表示尚无已验证成果。

## 有效范围与拦截

- 季计划绑定角色、年份、季节和目标版本。
- 修改长期目标后，旧季计划失效；换日后维护实际进度，换季后必须完成季节维护并生成新季计划。
- 旧记录仍可在预览中查看，但标记为已过期，不能授权动作执行。
- 模型单项动作、组合任务提交、组合任务每步派发，以及启用模型的 HTTP `/task` 入口均检查前置条件。
- `save_plan` 和组合技能保存的是短批次，不能代替季计划或玩家长期目标。

## 数据入口

- `GET /agent/planning`：当前目标版本、执行就绪状态、缺失原因和保存的季计划。
- 模型日常决策输入的 `planning` 字段包含相同内容，避免执行短批次后遗忘全季目标。
- 计划保存于当前运行目录的 `memory.db`，模型请求和保存回执写入 `logs/decisions.jsonl`。

本次变更不自动恢复或重跑此前无目标的测试。
