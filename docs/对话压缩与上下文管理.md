# 对话压缩与上下文管理

## 当前输入流程

普通决策只使用 `BuildDecisionInput` 构造输入，字段见[输入消息架构](输入消息架构.md)。`DecisionContextCompression` 仅提供 JSON 序列化、工具结果、回执摘要及查询表格编码；旧的整包上下文构建与回放代码已移除。

长期目标只读取显式保存的 `player_goal`。普通聊天不写入目标，缺失目标时等待玩家保存；历史聊天、旧指令和归档批次不自动变成当前工作。

季计划独立存储。只有符合当前字段结构、季节、年份和目标版本的计划才用于执行；缺失或过期时先生成完整季计划。换日后的维护请求只携带目标、当前日历、季计划和上一日成功回执。眼前执行批次使用 `group_*`，后续意图使用 `continuation`，均不表示已完成。

## 当前观察与反馈

当前世界投影包含地点、背包、作物、时间风险、邮箱、菜单和相关实体。列表附总数与截取标识；历史查询附日期、地点与观察版本。`observe` 成功后刷新本轮当前观察，工具回复只引用更新结果。

回执保留实际状态、原因、物品增量、体力和时间成本、原目标及业务详情。处理格、剩余掉落与碎片明细默认列出总数和四项样本，标记 `sampleOnly`；完整内容可分页读取。正文与成交目录不按处理格规则截断。

无选项提示由脚本确认；阻塞任务时，任务保留并在确认后继续，随后将提示与真实终态回执一起提供。需要选择的对话按原版实际选项处理。

当前主上下文软预算为 32,000 字符，不等于 token 上限，也不含系统提示、工具 Schema 和后续工具消息。超过预算时只移除非约定类相关记忆；当前观察、目标、弹窗和反馈保留。`input_projection` 记录字符数、软预算、超预算状态及工具目录字符数，实际 token 以 API usage 为准。

## 按需读取历史

`read_context_history` 只读取当前存档和角色的数据。参数为 `source`、`id`、`offset`、`limit`；`offset >= 0`，每页 `limit` 为 1–8。

| source | id | 返回内容 |
| --- | --- | --- |
| plans | 空字符串或计划 ID | 分页索引，或指定计划与执行证据 |
| memory | 空字符串、数字记忆 ID 或项目 GUID | 分页记忆索引、原文及历史执行证据 |
| receipts | 任务 ID | 实际回执及分页处理格、剩余掉落 |
| diagnostics | 本地记录 ID | 当前范围内的诊断记录，具体筛选见工具说明 |

完整计划、记忆、回执和日志保存在本地。历史证据需要当前观察核对，历史查询不会恢复旧目标或执行旧批次。
