## 1. 已修改

### 1.1 T044-S02 —— 迁舍失败 + 抚摸副作用（`src/StardewCompanion.Mod/NativeWorkCommerce.cs`）

**症状**：`animal_rehome_not_verified`，阶段 `approach_native_target`；后置快照 `petted=true`、好感 100→115，鸡 Tutsi 仍在原畜舍。

**根因**：无 `AnimalQueryMenu` 时代码走近动物并调用 `animal.pet(Game1.player)`。`FarmAnimal.pet()` 只做「抚摸（好感+、wasPet）」，**不打开** `AnimalQueryMenu`。于是每轮重试：抚摸一次（好感 +15）→ 菜单仍没开 → 再抚摸（`wasPet` 已置，无效）→ 直到超时。这既产生了不该有的好感副作用，又始终没进入 move-home UI，迁舍必然失败。

**修改**：把开菜单改为直接构造原版 `AnimalQueryMenu`，不再 `pet()`：
```csharp
// 旧：animal.pet(Game1.player); return "running";
Game1.activeClickableMenu = new AnimalQueryMenu(animal); _ownedMenu = Game1.activeClickableMenu; return "running";
```

**回答 Codex 之问**：
- 为何先抚摸？——原代码把 `pet()` 误当成“开查询菜单”的交互；实际 `pet()` 是纯抚摸副作用方法，开菜单应是构造/进入 `AnimalQueryMenu`。
- 副作用是否允许？——迁舍/查询任务不应改变好感。绕过 `pet()` 后无好感副作用。
- 迁舍失败与抚摸副作用**同源**（都是 `pet()` 误用），一并消除。
- 后续 move-home 点击坐标与 `animal.homeId` 核验（上一轮已加有界重试）待实机验证。

### 1.2 T028 —— `go_to` 反复切图不终止（`src/StardewCompanion.Mod/Navigation.cs`，我上轮的回归）

**症状**：补充 `go_to(Mountain)` 在 BusStop↔Backwoods 反复切图、未自行终止，由测试端取消。

**根因（回答 Codex 的 warp 计数之问）**：我上一轮把弹回从“直接 `blocked`”改成“恢复重试”，但 `_mapBounces` 在**每次正常过图**都执行 `_mapBounces=0`。A↔B 振荡的模式是「弹回→正常→弹回→正常…」：
- 弹回：`_mapBounces=1`
- 下一次正常过图（BusStop→Backwoods）：清零回 0
- 再弹回：又 1 ……

计数永远在 0/1 间摆动，到不了 `>3` 阈值，因此 `map_transition_bounced` 永不触发 → 无限切图。这就是“没有在边界内以明确失败终止”的直接原因，且是我上轮改动引入的回归（旧逻辑一弹回即终止）。

**修改**：
1. 正常过图**不再清零** `_mapBounces`（让振荡计数累积）。
2. 仅在到达目标（`Local` 返回 `reached`）与 `Reset()` 清零。

效果：弹回有界终止（约 4 次后返回 `map_transition_bounced`），恢复“明确失败”。这修的是计数器失效，而非单纯放宽次数。

**边界**：未解决 BusStop↔Backwoods **为何打转**的根因。可能是到达清场未让玩家离开来向 warp，或路由首边选错。需 Codex 提供的逐次 warp「起点/终点/当前位置/`_mapBounces`」序列才能定位，暂不盲改路由/清场。
