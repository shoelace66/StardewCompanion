# 工具分类、参数与返回说明

本文按当前源码中的工具注册表整理功能、参数和返回内容。工具会按存档能力、当轮模式、玩家授权工作箱和当前邮件状态动态显隐，因此模型每轮实际看到的工具可能少于本文列出的集合。组合工具会把同一类别下的业务工具作为 `steps` 子技能调用。

标记：`*` 为必填；`?` 为可选。类型和限制写在参数旁。`location` 通常填游戏机器地图名；坐标为地图格；`itemId`、`toolId`、`animalId` 等是游戏内部标识。购买商品使用显示名称 `itemName`。

| `read_mailbox` | 只读未读邮件正文模板和附件说明 | 无；仅有未读邮件时暴露 |

## 组合工具格式

八个类别组合工具分别为 `group_farm_management`、`group_resources_exploration`、`group_production_crafting`、`group_storage_economy`、`group_navigation_movement`、`group_construction_space`、`group_social_progress`、`group_character_schedule`。仅当前类别中至少有一个可用子技能时才暴露。每个组合工具参数为：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `planId` | 是 | 本次短计划唯一标识；同标识不会重复执行 |
| `steps` | 是 | 1–8个按序子步骤；每步格式 `{skill, arguments}`，skill只能是该类别当前可用技能 |
| `encounterPolicy` | 否 | 遇到普通矿井怪物时 `fight`/`avoid`/`interrupt`；默认 `interrupt` |

失败时停止后续步骤。工具调用只返回实际核验的进度；计划本身不算完成证据。

## 参数阅读提示

- `*` 表示必填，即使某个值不适用也可能要求显式传 `null`、空字符串或空数组；以本页每项说明为准。
- NPC姓名、动物类型、建筑类型和商品名称按各自的角色定义或真实菜单目录解析；同名不明确时需先消歧。
- NPC姓名由原版角色定义解析，脚本实时定位目标；物品名称可由原版普通物品/大工艺品目录解析，未入包物品也可识别。配方产物优先按所选配方消歧。目录只证明身份，不代表拥有材料、解锁配方或商店正在出售；未知/同名时返回原因和最多64个候选，并标明候选总数/是否截断。
- 普通商店购买的 `items` 使用名称 `itemName`。库存转移、出售、制作配方、捐赠等仍使用各自要求的内部标识。
- 地图边界、工具授权、能力状态等还会在执行前额外校验；本文列出的是调用参数，不代表目标当前可达或功能已解锁。

## 返回内容：通用结构与执行状态

本节描述当前实现实际返回的数据。返回值会随执行分支变化；列出的业务字段按需出现，不是每次都具备全部字段。没有专用数据的动作以通用回执、完成原因和后续观察为依据。

游戏查询和动作底层使用 `TaskResult`：`TaskId`、`Skill`、`Status`、`Reason`、`Details`、`Completed`、`ObservationRevision`。其中 `Details` 在协议中是JSON字符串。Core发送给模型时会解码、提取字段，下面以模型所见的小写开头字段名说明；部分嵌套对象仍保留源码字段的大小写。

| 返回字段 | 含义 |
| --- | --- |
| `taskId`, `skill` | 本次任务标识与实际技能名；组合工具的子任务各有自己的taskId |
| `status` | 执行状态，见下表 |
| `reason` | 具体完成、阻塞、拒绝或失败原因代码；可能带参数说明 |
| `completed` | 已核验完成量；单位须结合 `completedUnit` 和子步骤理解。复合技能的数量会累计不同子步骤，不能直接当作种植数、金币或完成目标数 |
| `observationRevision` | 产生回执时的游戏观察版本 |
| `requestedTarget` | 实际请求参数；模型投影会去掉内部箱子绑定和白名单字段 |
| `playerStart`, `playerEnd`, `location` | 执行前后玩家格子及结束地图 |
| `collectedItems` | 执行器记录的实际入包增量，通常为物品ID到数量的映射；并非预测掉落或利润 |
| `affectedTiles`, `remainingDrops` | 已处理格子和剩余掉落；模型摘要为 `{count, sample, sampleOnly}`，最多展示4条样本；完整明细可用 `read_context_history` 分页读取 |
| `actualCost` | `staminaBefore`, `staminaAfter`, `netStaminaUsed`, `healthBefore`, `healthAfter`，以及前后游戏日期/HHMM时间。交易金币另见业务明细的 `spent`、`income` 等字段 |
| `completedUnit` | 浇水为 `tiles`；区域收获/采集为 `items_collected`；其余为 `skill_units` |
| `businessDetails` | 按需含 `stages`, `activeStage`, `activity`, `encounters`, `skipped`, `storageTransfers`, `routeDrops` |

| `status` | 含义 |
| --- | --- |
| `accepted` | 已接收/派发，后续还有最终回执；不表示已经完成 |
| `completed` | 当前技能或批次已按实现核验完成；不自动代表模型写的长期目标已经完成 |
| `partial` | 已有核验进度，后续步骤失败或部分可选步骤不可用；必须查看已完成与未执行内容 |
| `failed` | 执行失败，查看 `reason` 和实际证据 |
| `rejected` | 参数、权限、能力或当前状态不允许执行；Core校验拒绝也可能只返回 `{status, reason}` |
| `cancelled` | 任务被取消；如已发生动作，应保留取消前实际进度 |

业务明细通常沿 `businessDetails.stages[].details.results[]` 读取。`stages[]` 含 `skill`, `status`, `reason`, `completed`, `details`；原生 `details` 含 `action`, `phase`, `verifiedCompleted`, `results`，还可能有 `pendingPurchaseEffect` 或 `activeTrade`。中断时正在进行的步骤保存在 `activeStage`。这些是分阶段证据列表，不是固定的一张成功结果表。

## 返回内容：组合工具与失败证据

八个 `group_*` 工具共用返回格式：正常提交为 `{status:"accepted", planId, steps}`；仅规划模式为 `{status:"saved_plan_only", executed:false}`；重复计划可为 `{status:"duplicate_not_executed", reason, originalFailure, results, unexecuted}`。执行结束后再交付批次结果：`planId`, `goal`, `status`, `reason`, `originalFailure`, `results[{step,receipt}]`, `unexecuted`，其中receipt按上述通用回执读取。

商店阻塞或商品匹配失败时，业务结果可含 `shopId`, `reason`, `phase`, `day`, `dayOfSeason`, `dayOfWeek`, `season`, `timeOfDayHHMM`, `openTimeOfDayHHMM`, `closeTimeOfDayHHMM`, `hoursSource`, `shopDialogue`, `releaseCondition`, `retryAtTimeOfDayHHMM`, `retryTimeKnown`, `verifiedPurchased`, `verifiedSpent`, `shopCurrency`, `extra`。未知时间保持null/未知，不推算下次开店日。

商品失败的 `extra` 含 `requested`, `remainingCount`, `catalog`, `catalogMeaning`。真实目录每项含 `itemName`, `internalName`, `quality`, `unitPrice`, `stock`, `unlimitedStock`, `bundleSize`, `tradeItem`；无限库存时stock可能为null。目录缺少某名称只证明当前菜单没有该项。

其他原生业务失败按原因提供 `failure`, `phase`, `location`, `gameDay`, `timeOfDayHHMM`, `verifiedCompleted`，以及相关的 `lastNativePrompt`, `inventory`, `tools`, `pendingTool`, `recipes`, `npcs`, `buildings`, `animals`, `quests`, `dialogueChoices`, `buildingOffers`, `animalOffers` 或当前shop目录。无关字段可能省略；定义目录只证明身份存在，不证明已解锁或当前可达。

`plan_continuation` 是后台建议提交工具：模型提交后，Core内部保存 `status:"hypothesis_requires_verification"`, `sourceDecision`, `predecessorTool`, `proposal`, `executionRule`；它没有普通游戏动作的成功回执。`mine_travel` 与 `complete_public_project` 当前未开放，调用不能获得有效执行成功结果，应以拒绝原因和当轮可用工具清单为准。

## 自动取料与按名寻路示例

以下为技能参数；组合工具调用时放在子步骤的 `arguments` 中。

```json
{"recipe":"Chest","count":1}
```

`craft_items` 先使用背包已有材料，再按授权工作箱的物品白名单取所缺数量。省略或清空 `sourceChests` 启用自动选择；非空列表保持指定来源范围。保护物不会自动取用；缺料时回报实际阶段与原因。自动候选中无路可达或失效的箱子会跳过，实际取物仍须接近并通过原有开箱、锁与转移核验。自动选择不读取远处箱子的实时内容。

```json
{"name":"Robin"}
```

`go_to` 按NPC的英文内部名或当前显示名实时定位，不要求最近观察过。脚本在移动期间刷新指定NPC的地图和格子；目标不存在、地点被禁用或原版门禁不可达时明确返回原因。到达NPC/授权箱旁停下，不触发对话或开箱。同名目标可加 `location` 消歧；唯一NPC的旧地图提示不会阻止跟随其新位置。

```json
{"location":"Town"}
```

地图名调用可只指定 `location`，进入目标地图即完成；也保留 `{"location":"Town","x":43,"y":57}` 坐标调用。`name` 还支持准确机器地图名或本地化地图显示名，以及玩家授权工作箱名。名称找不到或不唯一时返回候选供重新选择。

自动取料的来源候选记录在 `stages` 中 `skill:"ingredient_sources"` 的条目；实际取物看子步骤 `storageTransfers`，实际制作成功看 `received` 和 `verified`，不把“选择了来源箱”当成已取到材料。

上述自动取料规则也适用于 `cook_recipes`、`craft_and_place`、`install_irrigation`、`order_building` 和升级模式的 `modify_building`。灌溉在不制作时自动取缺少的现成洒水器，并按安装目标取所需附件；已安装的同款设施/附件不重复计入取物需求。保护物、授权白名单和预算仍需满足。

直接按姓名拜访，无需地图或预先查询位置：

```json
{"visits":[{"npc":"Robin","talk":true,"giftId":null,"quality":0,"dialogueResponses":[]}]}
```

任务送货可省略 `npc` 和 `location`，脚本读取任务中的实际交付对象；如仍提供npc则核对一致。领奖、取消通过原版任务日志完成，不先寻路。NPC、动物及宠物不存在、目标不唯一、路线锁定或地点被禁用时仍明确失败，不更换目标。

机器收取可按名称或区域选择，到场后识别并按距离排序，不要求模型逐台提供坐标：

```json
{"location":"Farm","machineName":"Furnace"}
```

```json
{"mode":"collect_and_load","location":"Farm","machineName":"Furnace","region":{"x":10,"y":10,"width":8,"height":8},"inputId":"铜矿石","quality":0,"fuelId":"煤炭"}
```

分别作为 `collect_outputs` 和 `service_machines` 的arguments。示例名称必须能精确匹配实际目录；不替换机器或原料。`location` 默认当前地图；未指定名称/区域时处理该地图全部符合条件机器。单次自动选择超过128台时要求缩小范围，避免静默漏掉目标。选择结果在 `machine_selection` 阶段列出真实坐标和物品ID；收产/装料结果仍分别核验。选中机器在执行前更换类型会返回 `machine_identity_changed`。

动物和宠物按ID跨地图定位，省略ID与地图时处理农场全部对应实体；指定地图而不指定ID时限制处理范围。选中实体清单分别记录在 `animal_selection` / `pet_selection` 阶段，随后逐个操作。喂食、产物收集和门状态按关联畜舍处理，宠物水碗按宠物ID关联，宠物不在水碗地图不会阻止加水。
