# 春季全流程自主经营测试计划

从第一年春 1 的新档开始，由 Agent 自主经营 28 天。春 28 夜完成原版结算与保存，在**夏 1 首个可操作的早晨**自动暂停，采集终局状态。按夏 1 现金、村民净好感、农牧场经营成果、工具升级四项评估。过程数据用于解释经营结果，并定位下一轮 Token 和响应时间优化。四项原始指标并列报告，默认不折算成一个总分。

## 1. 开跑条件与对照

- 等本轮工具修改合并到待测版本后，再固定 Core、模组、游戏、SMAPI、其他模组及测试入口版本。归档构建哈希、Git 提交及未提交改动说明、农场布局、存档 ID、可用能力、玩家禁用项、模型提供方、模型 ID、思考模式和完整初始目标。测试授权边界在开跑前确定。
- 使用隔离的原版单人新档，记录春 1 开工前的现金、物品、工具等级、NPC 好感和农场状态。春 1 是否有强制步骤要提前写进目标，各轮使用同一份文本。本方案默认允许模型自主决定开局消费和经营顺序。
- 正式运行只提交一次初始目标。观察者只读。若必须回答命名、绑定工作箱、提供策略、补做、重载或重新启动，记录 UTC、游戏日、原因及操作，标记为有干预。原版自动确认的无选项通知单独统计。
- 先跑一轮完整春季，建立经营与性能基线。比较 Schema 时，两组使用同一工具实现、模型配置和目标，只改变日常 Schema 筛选。优先使用同一初始世界条件的隔离测试存档及独立 Agent 数据目录。现有单人启动脚本每次创建新档，无法配对时记录世界差异，再用同一批真实上下文发模型请求，通过离线回执比较工具选择与开销。单次跨存档表现仅作观察。

### 初始目标模板

> 自主经营第一年春季，在春 28 夜完成原版结算与保存，夏 1 早晨停止。兼顾季末现金、村民净好感、农牧场可持续经营和已取回的工具升级。自行制定季计划，根据日期、实际余额、剩余体力、作物周期、商店时间和已验证回执安排工作。遵守玩家授权及禁用技能。按观察和原版回执确认结果，受阻时说明原因并在可行范围内继续。建设或升级订单需核对实际完工或取回状态。

## 2. 夏 1 主评分与核验

以春 28 夜结算完成后、夏 1 任何生产或交易开始前的**原版存档与状态**为主证据。动作回执用于解释来源。

| 评分项 | 统一口径 | 附带数据 |
| --- | --- | --- |
| 金币 | 夏 1 现金余额。现金净变化为期末减期初。春 28 夜到账的出货收入计入春季一次 | 按出货、商店直售、任务及其他收入分组，按种子、经营投入、建筑、动物、工具升级及损失分组。记录未售存货的物品 ID、品质和数量，库存估值单列 |
| NPC 好感 | 按原版 NPC ID 对比春 1 和夏 1 的原始好感点数，列逐人净变化、正向人数和净变化合计。对经完整存档核验后确认为无记录的 NPC 按 0 计 | 记录重点村民、实际对话及送礼回执以解释涨跌。看不到或无法核验的值标为缺失 |
| 农牧场经营 | 记录实际完工可用的建筑、存活动物及其安置、实际产出，以及可继续经营的耕地、设备和库存。保留每项原始数量 | 建筑类型和完工日、动物类型和入栏日、产物累计数、已实现的收获与播种规模、夏 1 可用地块及补给。施工中、孵化中、已下单和待收取项目分别列出 |
| 工具升级 | 按工具类型列初始等级、夏 1 已实际取回的等级、等级提升数与取回日。核对背包、工作箱或原版工具状态 | 在升级、已完成待取和已取回分别记录。钱包扣款和订单回执用于核对支出 |

## 3. 还要采集的数据

### 每日经营记录

每天记录开工和夜间结算后的现金、资金流水、收获和种植数量、观测到的最低体力、睡觉时间、过去一天的天气及主要事件。关键交易保留游戏时间、金额、数量和回执 ID。春 1 开工前保存只读原版观察，春 8 / 15 / 22 早晨及夏 1 留存夜间写入完成的存档副本。春 28 另记睡前现金和最后一夜结算。逐日对账使用 `期末现金 = 期初现金 + 已到账收入 − 已扣款支出 − 已确认损失`，无法归因的差额单列。

记录关键决策的**触发、选择、实际结果、恢复**。优先关注种子补货和季末停种、未浇水或错过收获、动物断粮或漏收、升级排队及取回、节日或店铺时间窗、体力耗尽与昏倒。若要比较动物照料率，以已入栏且需照料的动物日作分母，用当天照料回执或睡前状态核验，缺失的动物日单列。

### 模型成本、延迟与可靠性

| 项目 | 采集与计算 |
| --- | --- |
| 调用和用量 | 按日常行动、必需季计划、季计划维护、后续预规划和离线聊天分组。记录请求数、成功回复数及缺失 usage 的数量。有同一请求的重复发送证据时单列重试。汇总 `prompt_tokens`、缓存命中/未命中、`completion_tokens`，以及供应商有返回时的推理 token。按供应商实际计费口径算整季费用 |
| Schema 成效 | 从 `model_request` 取工具数、`toolsCharacters`、`toolsExpanded`，统计包含展开的决策比例与展开后实际用到新增技能的次数。用同一 `DecisionId` 汇总各轮，报告每个至少产生一项经核验游戏成果的决策所用 Token 和请求数，并保留失败决策的总开销 |
| 响应时间 | 记录模型单轮 `elapsedMs`、首个日常请求到首次有效派发、上一动作终态到下一次新决策的有效派发，以及派发到终态。短计划内部的步骤间隔单列。各项报告样本量、P50 和 P95，超时与无派发的决策另列 |
| 等待与预规划 | 对耗时样例标记计划内主动等待、菜单、断线、退避或预规划。记录预规划请求、产生提案、超时或丢弃的次数，并对照上一任务终态时间判断是否延迟下一步 |
| 执行质量 | 按技能统计已派发、完成、部分完成、失败、拒绝、取消、无进展和重复尝试。记录失败原因与目标，附上派发参数、回执和新观察。一次派发按 `TaskId` 取其终态，接单与进度事件分开统计 |

优先用 `Scope`、`Session`、`DecisionId` 关联决策，用 `requestId` 关联模型轮次，用 `TaskId` 关联派发和回执。没有 `requestId` 的旧事件或预规划按类型和事件顺序对齐，无法可靠匹配时记缺失。时间差用日志 `At` 的真实时间。游戏时钟用于解释一天内的经营机会。单列回执缺失、人工干预、换日维护和有意等待，计算连续动作间延迟时注明是否包含它们。

## 4. 运行步骤与归档

1. **先做采集冒烟。** 确认能读到长期目标、原版存档位置、全体村民好感、农场建筑和动物、工具等级及待取状态。抽查一次模型调用和一个任务能跨事件对齐。优先用原版存档的只读副本补采全档数据。现有观察采样有地图范围和时间间隔，无法覆盖的值保留缺失标记。
2. **启动正式测试。** 把上方目标保存成 UTF-8 文本。以下命令使用仓库的 28 日自主入口，路径按本机配置填写。当前脚本会校验配置中的模型 ID，开跑前在待测版本中确认它接受所用模型，并验证连通和工具调用。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-solo-five-days.ps1 `
     -Autonomous -Days 28 `
     -InitialInstructionFile .local/spring-season-goal.txt `
     -SettingsFile '.local/model.credentials.json'
   ```

3. **运行中只读记录。** 保留完整日志，按检查点复制已写好的存档。卡住时先保留最后的原版状态、待处理菜单、日志序号及错误。中断恢复使用同一隔离存档及原目标，记录恢复点、版本以及是否发生回档。回档前的消耗仍计入实测运行成本，回档撤销的成果从最终经营统计中剔除。
4. **夏 1 封存。** 核对 `GameDay=28`、日历为夏 1、空菜单、无活动任务，检查 `trial_completed`、原版存档写入和夏 1 行动记录。先复制存档，再打开界面检查。未到夏 1 标记为未完成，记录最后完成的游戏日和具体阻塞。到达夏 1 但有人工接管或证据缺失时，保留成绩并标注影响范围。

| 应归档材料 | 来源 |
| --- | --- |
| 版本和开跑条件 | `trial.json`、构建哈希、`initial-instruction.txt`、已保存长期目标与脱敏模型配置 |
| 完整决策与执行证据 | `decisions.jsonl`、`observation-snapshots.jsonl`、`autonomy-status.json`、`world.json`。出错时附对应时间段的 SMAPI 日志 |
| 原版结果 | 春 1 与夏 1 原版快照、中间检查点存档副本、夏 1 四维结果表、现金对账及人工干预记录 |

交付报告保留每项结果的证据路径和无法核验的缺口。判断 Schema 是否值得保留时，同时比较**每次有效决策用量、动作接续 P95、工具成功率以及夏 1 四项结果**。分享归档时移除 `session.json`、密钥和其他私密字段。
